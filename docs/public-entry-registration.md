# Public entry and registration

Home, the catalog, published result summaries, rules and `/how-it-works` are public display surfaces. Telegram's signed launch is established in the background. Personal routes render an account gate; wallet, profile, bids, notifications, payments and all mutations still require server authorization. Published participant-contact drilldowns retain their registered-account boundary.

`useTelegram().openRegistration()` opens one lazy, dismissible registration sheet. Only **Share contact** invokes Telegram's native `requestContact()`. Declining, closing, unsupported clients or a delayed callback leave public browsing and the bid draft intact. SDK approval is not registration: bounded polling waits for the authenticated bot webhook's own-contact proof, then `/api/me` confirms the bound account. Existing registered users recover automatically through their signed launch.

The contact transaction retains sender/chat/contact identity, bot binding, anti-forwarding, encryption, collision and revocation checks. It commits contact proof and a unique `CONTACT_CONFIRMED` outbox job atomically. Optional confirmation delivery runs in the existing notification worker, independently of registration. Ordinary bot commands also release their durable inbox claim before Telegram delivery; a two-minute lease permits restart recovery. As with other Telegram delivery jobs, a crash after send can repeat a message but never a registration, bid or ledger effect.

The command worker continues to use `npm run worker`; the existing notification worker uses `npm run worker:notifications`. No new environment variable or migration is needed for this registration change. Run `npm run bot:setup` against the intended bot when updating its menu text to **Open Lowwin**. `/start` sends one concise welcome and one launch button for every private user. Valid opaque payment-resume links and referral attribution remain supported; a start parameter never proves payment or ownership.

Public display responses use the persistent browser QueryClient under `lowin-public`; private responses stay under `lowin-private` plus the session identity. Account changes cancel and remove private reads without discarding public snapshots or public list coordinates. Capability/payment calls remain off public Home's critical path. No phone number, permission grant or registration marker is stored in browser storage.
